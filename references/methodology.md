# 方法论详解

本文档记录 chem-research-loop 的算法定义、评分公式、参数含义与调参经验。
所有公式与阈值都来自实测校准，不是理论假设。

---

## 一、跨源去重：双指纹联合判定

### 问题

同一篇论文会在多个数据源出现，元数据不一致：

| 情况 | OpenAlex | Crossref | arXiv |
|---|---|---|---|
| DOI | 有 | 有 | **常常没有** |
| 标题标点 | `metal–organic`（en dash） | `metal-organic` | `Metal Organic` |

若采用「有 DOI 用 DOI，否则用标题」的单键策略，arXiv 记录（无 DOI）与
OpenAlex 记录（有 DOI）永远无法匹配为同一篇 —— 实测 20 条原始记录去重后仍是 20 条。

### 解法

同时维护两个索引，任一命中即合并：

```
doi_index:  规范化的 DOI  -> 首次出现的记录下标
title_index: 标题指纹      -> 首次出现的记录下标
```

**标题指纹**定义：

```
归一化：去除非字母数字字符（保留中文）→ 转小写
有效条件：归一化后长度 >= 20 字符
截断：取前 110 字符
```

长度门槛是必要的：`Editorial`、`Correction`、`Erratum` 这类短标题若参与匹配，
会把毫不相关的文献合并到一起。

**传递性合并**：被合并记录的指纹也要登记。这样 A~B 靠 DOI、B~C 靠标题时，
三条会被正确归组。

### 合并时的字段择优

以「信息丰富度」决定保留哪个版本：

```
richness = len(abstract) + 10 * len(authors) + len(venue)
```

但引用数取 **max** 而非保留非空 —— 不同源的统计口径与时点不同，最大值更接近真实。
（实测教训：早期用「保留非空」，导致 120 次引用的记录被 100 次的覆盖。）

## 二、概念抽取：同义词归并

### 为什么必须归并

假设真实语料中 MOF 出现 100 次，但书写形式分散为：

```
MOF(30)  MOFs(25)  metal-organic framework(25)  metal organic framework(20)
```

若不归并，统计结果是「4 个概念各出现 20~30 次」，没有任何一个能跨过
频次门槛（语料 100 篇时门槛为 3，看似能过；但在语料 30 篇、门槛 2 的
场景下，这 4 个概念会被拆散成 4 条互相竞争的弱信号）。

更严重的是会**污染空白候选**：`MOF × X` 与 `metal-organic framework × X`
实为同一条，却会各占一个候选位。

### 实现

`COMMON_SYNONYMS` 定义 225 条规范名到书写变体的映射，覆盖化学四方向的高频术语。

术语编译为**词边界正则**，兼容多种书写：

```python
term = "metal-organic framework"
# 分隔符 [\s\-–—/]+ 使以下全部命中：
#   metal-organic framework
#   metal organic framework
#   Metal–Organic Framework   (en dash)
#   metal/organic framework
# 前后加 (?<![A-Za-z0-9]) / (?![A-Za-z0-9]) 防止匹配到更长词内部
```

## 三、空白探测：结构洞式组合分析

### 形式化定义

设语料含 N 篇文献。对概念 a、b：

```
freq(a) = 出现 a 的文献数
co(a,b) = 同时出现 a 与 b 的文献数
expected(a,b) = freq(a) × freq(b) / N     ← 两概念独立时的期望共现
```

**候选空白** = 满足以下全部条件的跨类别组合：

```
freq(a) >= min_freq          # 两侧各自都有足够文献支撑
freq(b) >= min_freq
expected(a,b) >= min_expected # 语料足够大，"本该有共现"
co(a,b) 显著小于 expected     # 但实际几乎没有
```

直观解释：**这两个概念各自都有人研究，却没人把它们放在一起。**

### 三重防误判

| 防线 | 作用 |
|---|---|
| `min_freq` 门槛 | 排除「本身就没人研究」的概念，那不是空白而是冷门 |
| `min_expected` 门槛 | 排除「语料太小导致必然零共现」的假信号 |
| 证据锚点 | 每条候选附带两侧概念的**代表文献**，供复核 |

### 自适应门槛

固定绝对门槛会在小语料下失效（实测：18 篇语料 + 门槛 3 → 空白候选 0 条）。
因此门槛随语料规模缩放：

```
min_freq:      N < 50 → 2 ;  50~150 → 3 ;  150~400 → 4 ;  > 400 → 5
min_expected:  N < 50 → 0.6 ;  否则 → 1.0
```

### 评分公式

| 维度 | 公式 | 含义 |
|---|---|---|
| novelty 新颖性 | `1 - min(1, co/expected)` | 共现越低于期望越新 |
| evidence 证据强度 | `min(1, expected/2)` | 期望越高说明「本该有研究」越强 |
| feasibility 可行性 | `min(1, (freq_a + freq_b)/12)` | 两侧文献越充分，命题越容易检验 |
| momentum 动量 | 两侧概念近三年文献占比的均值 | 反映是否处于上升期 |

```
score = 0.40·novelty + 0.25·evidence + 0.20·feasibility + 0.15·momentum
```

权重可在 `analyze.py` 顶部的 `W_*` 常量调整。默认偏重新颖性，符合
「找研究切入点」的核心诉求；若目标是「找可落地的方向」，应提高 feasibility 权重。

## 四、反证实验：唯一的真值来源

### 为什么统计信号不够

**语料内零共现 ≠ 真空白。** 语料来自有限几条检索式的返回结果，
只是领域的采样，不是全样本。

### 实验设计

对每条候选，构造带**领域锚点**的精准查询：

```
"{anchor}" "{left}" "{right}"
{anchor} {left} {right}
```

例如 `"MOF" "defect engineering" "CO2 capture"`。

**锚点为何必需**：不加锚点时查 `catalysis selectivity`，返回的是全学科通用
催化文献。这些文献虽同时含两个术语，却与本研究主题无关，会把本领域的真实
空白误判为「已被研究」。实测：不加锚点时 8/8 条候选被推翻；加锚点后同一批
候选的交叉数从 13 降至 7，判定回归合理。

### 判定规则

只统计**同时满足**「属于本领域（含锚点）」且「同时含左右术语」的文献：

```
cross_rate = co_hits / retrieved

co_hits == 0                          -> 确认（空白成立）
co_hits >= 3 且 cross_rate >= 0.10    -> 推翻（交叉密集，假空白）
其他                                   -> 存疑（交叉稀疏但非零，需人工判读）
```

用**交叉密度**而非绝对篇数：20 篇命中里 2 篇交叉（10%）与 5 篇命中里
2 篇交叉（40%），含义完全不同。

## 五、迭代控制

```
第 n 轮：验证 pending 队列头部 verify_top 条
  ├─ 累计到 verified_keys，跨轮去重（防止重复验证同一组合）
  ├─ 若 推翻数 > 确认数 且 未达轮数上限：
  │     判定为语料覆盖不足 → 放宽门槛（min_freq=2, min_expected=0.7）
  │     重新探测一批新缺口，追加到队列
  ├─ 若 确认数 >= max(2, verify_top)：收敛，提前退出
  └─ 队列耗尽：自然收敛
```

**为什么「推翻偏多」要触发放宽而不是收紧**：推翻说明候选被真实研究打脸，
根因通常是语料覆盖不足导致大量组合呈现假零共现。放宽门槛可以把更多
「低共现但非零」的组合纳入考察，而不是在原有的窄候选集里反复打转。

## 六、调参速查

| 症状 | 处置 |
|---|---|
| 空白候选 0 条 | 提高 `--depth` 增加语料；或在 `domains.py` 补 `concept_seeds` |
| 候选全是泛概念组合（如 catalysis×selectivity） | 提高 `min_expected`（建议 1.5~2.0），过滤掉「本该大量共现」的组合 |
| 候选过多、验证太慢 | 降低 `--max-rounds`，或减小 `verify_top` |
| 大量候选被推翻 | 正常现象，说明反证在工作；若比例 > 90% 考虑提高 `min_expected` |
| 某概念频次异常低 | 检查 `COMMON_SYNONYMS` 是否收录其缩写/变体 |
| 检索结果与主题偏离 | 换更具体的 `--topic`，或加 `--year-from` 聚焦 |

## 七、已知局限

1. **概念粒度偏粗**。词典以领域通用术语为主，无法识别「潮湿烟气条件下
   MOF 的缺陷工程」这类细颗粒度命题。这类细分空白需要 Agent 在证据包
   基础上做语义推理补足。

2. **只覆盖摘要文本**。付费墙文献若摘要缺失，仅能匹配到标题，贡献有限。

3. **中文文献未覆盖**。当前四个数据源以英文文献为主，CNKI/万方未接入。

4. **成熟领域难以产出「确认」空白**。这是方法论的诚实结果，不应通过
   放宽标准来制造结论。

## 八、V2 工程机制：门禁、知识库与断点

### 8.1 为什么需要独立审稿层

上游各阶段「自证清白」不可靠。V2 引入独立审稿人，核心是**不接受任何自我声明**：

| 上游声称 | 审稿人动作 |
|---|---|
| 语料 103 篇 | 自己数 papers.json |
| MOF 出现 78 次 | 调用同一套抽取逻辑重算 |
| 该锚点文献存在 | 到语料里比对 ID 与标题 |
| 这是研究空白 | 复核反证过程留痕与交叉密度 |

实测收益：抓出过「命题库静默丢失 3 条记录」（4 条假设被写进同一文件互相覆盖）、
「复算口径不一致产生假告警」等真实缺陷。

### 8.2 确定性证据门禁的设计取舍

门禁分为两类：

- **确定性门禁**（G01–G04）：纯计算、不联网、结果可重复 —— 无条件作为交付前闸门
- **网络型反证**（第 ⑤ 阶段）：依赖外部 API、存在波动 —— 放在实验阶段，其结果本身被门禁校验

划分的意义：**交付闸门不能依赖网络可用性**。把「必须可复现」与「依赖外部」
两部分分开，门禁才真正可靠。

### 8.3 静默失败的防范（最重要的一节）

最危险的缺陷不是崩溃，而是**不抛异常的数据丢失**。实测遇到两例：

1. 命题 ID 解析只查顶层字段，取不到就退化为 `P000`，导致 4 条假设覆盖成 1 条
2. `--reset` 只清状态不清产物，陈旧文件混入新一轮，命题库出现幽灵记录

两者共同点：**流程照常结束、报告照常产出，只有条数校验能发现**。
因此专设检查 C20「命题库记录数与实验过程一致」，比对「库中条数」与
「实验累计验证条数」。

**可推广的推论**：凡是「上游产出 N 条、下游消费 M 条」的地方，
都应加一条 N vs M 的一致性检查。这类检查成本极低，却能拦住最隐蔽的缺陷。

### 8.4 状态恢复的边界

断点续跑要恢复的不只是「跑到哪了」，还包括**上下文数据**：

| 需恢复 | 用途 | 漏恢复的后果 |
|---|---|---|
| papers | 后续所有分析 | 直接报错 |
| analysis | 报告组装 | 直接报错 |
| propositions | 审稿与报告 | 报告缺结论 |
| **ledger** | 审稿人核对数据源可用数 | **误报阻断，拒绝交付** |

最后一行是实测踩到的：只恢复了业务数据、漏了元数据台账，审稿人看到
「在线 0 个」而阻断交付。**机制是对的，缺的是状态** —— 这也反过来说明
门禁确实在起作用。

### 8.5 可复算性的一体两面

审稿人的复算**必须复用上游同一套逻辑**，而不是另写一套等价实现。

反例（实测踩坑）：复算共现时只匹配规范名 `MOF`，而上游统计包含
`MOFs` / `metal-organic framework` 等全部同义词变体，于是报出
「声明 48、复算 33」的假告警。

结论：**口径不一致的复核，本身就是缺陷来源**。正确做法是共享术语定义、
仅让计算路径独立（一个走集合交集、一个走逐篇判定），这样既能发现真问题，
又不会因实现差异产生噪声。
